# Data model and the synthetic deal

All data is JSON in `/data`. Types in `lib/types.ts`. Fixtures are generated by `scripts/gen-fixtures.ts` from the hand-edited names files so they can be rebuilt.

## Types

```ts
type Stage = 1 | 2 | 3 | 4 | 5;           // sourcing, diligence, close, portfolio, exit
type Room = "deal" | "portfolio";

type Person = { id: string; name: string; role: "partner" | "director" | "vp" | "associate" | "analyst"; isCurrentUser: boolean };
type Party  = { id: string; name: string; kind: "accounting" | "legal" | "hr" | "it" | "lender" | "banker" | "seller" };

type Company = { id: string; codeName: string; sector: string; room: Room };

type Lane = { id: string; companyId: string; name: string; kind: "workstream" | "memo"; ownerId: string; externalPartyId?: string };

type Item = {
  id: string; laneId: string; title: string; ownerId: string; dueDate: string;
  status: "notStarted" | "inProgress" | "blocked" | "done";
  doneLooksLike: string;                 // what proves it
  evidenceIds: string[];
};

type Evidence = {
  id: string; kind: "email" | "file" | "requestListUpdate" | "qaEntry" | "note";
  from: string; partyId?: string; receivedAt: string; subject: string; body: string; attachmentName?: string;
};

type Proposal = {
  id: string; evidenceId: string; itemId: string;
  proposedStatus: Item["status"]; quotedSource: string;
  strength: "clear" | "thin" | "conflict"; conflictNote?: string;
  decision?: { by: string; at: string; action: "approved" | "rejected" | "askedForConfirmation"; reason?: string };
};

type MemoSection = { id: string; name: string; placeholder: boolean; supportedBy: string[] /* laneIds */; coverage: "full" | "partial" | "none" };
type SellerQuestion = { id: string; laneId: string; text: string; askedAt: string; dueAt: string; answered: boolean };
type BidChecklistItem = { id: string; name: string; placeholder: boolean; done: boolean };

type ActivityEntry = { id: string; at: string; by: string; action: string; itemId?: string; evidenceId?: string };
```

The Portfolio Room later reuses Company, Lane (kind "initiative"), Item (a commitment with a month), Evidence (kind "monthlyReport"), Proposal, and ActivityEntry unchanged. Do not special-case the Deal Room in the types.

## The synthetic deal: Project Beacon

- **Target:** Beacon, a regional specialty logistics and cross-dock operator, founder-owned, sell-side run by a fictional bank. Not aerospace. Not any real company.
- **Deal clock:** IC approved the Criteria Worksheet on day 0. IC memo and final bid due day 30. Demo "today" is day 21 in `midstream` (9 days to IC). Bid deadline to the banker is day 33.
- **Team (fictional names, real roles):** Partner, Director, VP (current user), Associate, Analyst. `team.json` is hand-edited so real names can be swapped with consent.
- **External parties:** one accounting advisor, one law firm, one HR advisor, one IT advisor, two lenders, one bank, the seller.

6. Email, Lender B, two days later: term sheet attached. Clear.
7. Calendar invite: management meeting, day 26.
8. Email, AJ's status note from yesterday (the structure the draft learns from).

Items 1, 2, and 10 are the three in the inbox when the demo opens. The rest are already processed or arrive through "simulate evidence arriving."
